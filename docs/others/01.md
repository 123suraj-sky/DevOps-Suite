* Keep the **Azure configuration/workflow code** in your repository if you want to demonstrate Azure deployment.
* **Do not keep Azure secrets exposed in the repository.**
* Your Azure credentials should remain stored as **GitHub Secrets**.
* Once the Azure subscription is disabled, those credentials will simply stop being useful for deployment.
* You can later remove/rotate them when you no longer need Azure.

### What I'd recommend for your project

Since you've already deployed DevOps Suite to Azure, **don't change anything right now**.

Use the remaining Azure period to demonstrate:

**Phase 1**

> GitHub → GitHub Actions → Azure VM → Docker → running application

Then add:

**Phase 2**

> GitHub → GitHub Actions → GHCR → Docker image

Then, after Azure expires:

**Phase 3**

> GHCR → another VM/cloud provider → same Docker image

This actually makes your project stronger because you can say:

> **"The application is containerized and cloud-provider independent. Azure is one deployment target, while the Docker image can be deployed to any compatible environment."**

And yes, **keep your Azure credentials in GitHub Secrets while you still need the Azure deployment workflow**. Just don't rely on them after the subscription becomes inactive.
